# Purpose of This Document

This file governs *how* work gets done. The companion document, `v8.0.md`, governs *what the program currently contains*. If you are an AI agent picking up a task inside this research program — deep research, a proof attempt, a literature survey, a construction, an adversarial review — read this file first, in full, before touching the content of `v8.0.md`.

The single sentence that summarizes everything below: **ideas enter free, promotion costs debt, and no mathematical elegance excuses you from checking whether the thing you're proposing is native to the component you're proposing it for.**

# Part 1 — EBP v2.1: The Core Constitution

1. **Ideas enter free.** No idea is rejected at the door for being unlikely, unfashionable, or previously abandoned. Entry costs nothing. `needMap`, `needInvariant`, `needToyCheck`, `needNullModel`, `needObstruction`, `needFaithfulnessReview` — the six debt items — are what an idea owes before it can be *promoted*, not before it can be *proposed*.
2. **Promotion costs debt, and debt is retired by doing work, not by writing prose about the work.** A claim is promoted only when its stated debt items are actually retired: a map is drawn, an invariant is computed, a toy case is checked, a null model is run and beaten, an obstruction is searched for and not found, the formalization is checked against the intended claim.
3. **Debt blocks promotion. It never kills an idea.** An idea with open debt sits in the ledger as OPEN, TARGET, WORKBENCH, or RESERVED — never DELETED. New contradicting evidence can reinstate debt on a previously-promoted claim and unpromote it.
4. **No final-truth language is ever promoted.** Every promoted claim carries its scope and its falsification condition alongside it, permanently.
5. **A session that retires no debt, files no obstruction, and captures no new idea was probably entropy.** This is the minimal session rule. Producing a long document is not the same as producing progress; check which debt items actually moved before calling a session productive.
6. **Accounting must never become the work.** If you find yourself restating the same open task across four different sections instead of attempting it once, you have confused bookkeeping with research. Consolidate; don't multiply.
7. **A rejected claim is recorded, not deleted.** Keep the specific failure mode on file (which hypothesis failed, which citation was misattributed, which null test the claim didn't survive) so it is not silently re-attempted with the same error six months later.

# Part 2 — The Reality-First Principle

## 2.1 The master assignment rule

Before proposing that any mathematical structure belongs in the active architecture, answer one question: **which of the four components — Dancer (matter/energy), Dance (mechanism), Stage (spacetime), or a cross-cutting invariant of the other three — is this structure being proposed for, and is the mathematics you're reaching for actually native to that component?**

Native means: independently confirmed, across the fifteen-branch survey below, to do real explanatory work for that component in established physics — not merely capable of being written down in a way that resembles that component.

## 2.2 The generator/invariant distinction

This is the single most load-bearing distinction in the whole checklist:

$$
\boxed{\text{What makes a system happen?} \;\neq\; \text{What remains true about the system once it has?}}
$$

Dynamics answers the first question. Invariants answer the second. Of everything surveyed, **only calculus answers the first question.** Every other branch — arithmetic included — answers only the second, and only for specific, checkable classes of quantity. Do not let a structure that answers the second question be mistaken for, or quietly substituted as, an answer to the first.

## 2.3 The fifteen-branch digest

| Branch | Native domain | Explicitly dead/silent on |
|---|---|---|
| Algebra | Grammar of symmetries, representation theory, composition | Dynamics, particle content, probability, spacetime generation |
| Arithmetic | Spectral/invariant fingerprinting when values are algebraic | Dynamics, spacetime, gauge selection, prime selection |
| Calculus | **The only confirmed engine** — motion, fields, dynamics | Initial conditions, probability, particle content, discrete structure |
| Chaos | Sensitivity, attractors, statistics of nonlinearity | Equations of motion themselves, initial state, probability |
| Complexity | Cost/difficulty of prediction, decoding, erasure | Which problem is posed, which probability applies |
| Degrees of Freedom | Inventory/counting of state space | Dynamics, initial conditions, probability, interactions |
| Duality | Translation between equivalent descriptions | Equations of motion, initial state, probability |
| Emergence | Collective/scale-dependent effective law | Fundamental dynamics, initial conditions, probability |
| Entropy | Irreversibility, information currency | Equations of motion, initial state, probability |
| Geometry | Stage of spacetime, shape of state space | Quantum probabilities, particle content, initial conditions |
| Invariants | What survives translation between descriptions | Dynamics, initial conditions, probability, state-space architecture |
| Langlands | Reciprocity between number theory and gauge theory | Dynamics, initial conditions, probability |
| Spectra | Fingerprint of every operator | Which operator defines it, dynamics-generation, probability |
| Symmetry | Conservation, classification, gauge structure | Dynamics, initial conditions, probability, spacetime dimension |
| Topology | Census of defects/phases/global structure | Shape, scale, dynamics, class-selection, probability |

**The one silence every branch shares:** none of the fifteen explain the Born rule. If a proposal claims to have solved this via any one of them, that claim gets the highest level of scrutiny in Part 4, not the benefit of the doubt.

## 2.4 The "successes get the same scrutiny as the failures" rule

A structure is not exempt from the null test just because it's the one still standing after others failed. Every one of the fifteen branches' claimed "wins" — modular invariance in a CFT, a trace formula on an arithmetic surface, a topological invariant with algebraic content — must be run through the same existing-theory null (Part 4) that killed the rejected candidates, before being counted as a confirmed native role rather than an unexamined survivor.

# Part 3 — The Arithmetic-Specific Checklist

Arithmetic is this program's single most tempting overreach, because it is genuinely, deeply beautiful mathematics, and beauty is not evidence. This checklist exists because of that specific risk.

## 3.1 The re-entry condition (full statement)

Arithmetic re-enters the active architecture only when a construction built with zero arithmetic content produces an invariant whose values require an algebraic number field, a modular form, a Galois action, or an L-function to state precisely — not merely an integer, not merely a rational number arising from ordinary counting.

## 3.2 The three-question test, applied to any candidate invariant

1. **Is it discrete because of topology or ordinary symmetry?** (A winding number. A Chern class. Angular-momentum quantization from SU(2).) → Stays with topology/symmetry. Arithmetic does not enter.
2. **Is it a generic, continuously-varying real number?** → Arithmetic is inapplicable.
3. **Does its exact value require algebraic/modular/Galois structure to state?** → This is the only case where arithmetic's reserved material may be reopened, and only the specific piece matching that structure.

## 3.3 Named traps to check against explicitly

- **Integer-valued ≠ arithmetic.** Most of the integers in physics (Chern numbers, winding numbers, mode numbers) belong to topology or symmetry. Check which, before reaching for number theory.
- **Discrete ≠ arithmetic.** A discrete spectrum from a bound-state problem is calculus/geometry's native output, not evidence of an arithmetic substrate.
- **A single mod-p residue is not an arithmetic-specific structure.** It is definitionally identical to an ordinary finite cyclic register. Nesting across multiple scales/valuations is the minimum structure that could possibly distinguish "arithmetic" from "generic finite group."
- **A real, existing precedent for using arithmetic machinery as a physical constraint (e.g., an adelic product formula in a toy string amplitude) is not the same as a demonstrated need for it here.** Precedent that the *strategy* has been tried is not evidence the *specific application* is warranted.
- **"The math is elegant" is not a debt-retirement event.** Elegance is a reason to keep an idea in the reserve library, not a reason to promote it.

# Part 4 — Adversarial and Citation Discipline

## 4.1 Function-class typing before derivation

Before attempting to close any gate, state in one sentence what *kind* of claim is being made — existence theorem, selection principle, construction, phenomenological fit, or analogy — and check that the specific object in front of you actually satisfies the hypotheses of whatever theorem is about to be invoked. Do not check the hypotheses of a nearby object with the same name.

## 4.2 Borrowed rigor is its own failure category, worse than an unproven claim

A claim dressed in a real, correctly-cited theorem, applied to an object that does not satisfy that theorem's hypotheses, reads as settled on a skim. It is not settled — it is often worse than an admittedly-speculative claim, because it actively misleads. Tag any such claim `[BORROWED]`, not `[SPECULATIVE-SHAPE]`.

## 4.3 Citation verification is mandatory, not optional, for every load-bearing reference

- Read the actual claim in the source, not just the title or abstract.
- Confirm the citation supports the *specific point* attributed to it, not merely a nearby or thematically-adjacent point.
- Flag, explicitly, any source from an unreviewed or AI-content-adjacent venue (self-published preprint servers with no review process, AI-assisted-content archives, forum or social-media posts used as if they were academic sources) — such sources may still be reported, but never as load-bearing evidence, and always with their provenance stated plainly.
- A citation you cannot personally verify at this level of confidence is marked `UNVERIFIED — recommend independent check`, never silently included as settled support.

## 4.4 The null-model hierarchy — use the right one, not just any one

| Null type | What it checks | When to use it |
|---|---|---|
| **Generic-clock/matched-generic null** | Would an ordinary, non-arithmetic construction of the same size/complexity reproduce this result? | Any claim that a specific mathematical structure (not just "some structure") is doing the work |
| **Decoupled null** | If you remove the proposed coupling/interaction term entirely, does the prediction change? | Any claim that two components are physically coupled, not just mathematically adjacent |
| **Existing-theory null** | Is this phenomenon already fully explained by established, non-arithmetic physics (topology, gauge theory, an existing CFT construction)? | Any claim that a real physical phenomenon constitutes evidence for the program's own mechanism |

Running the wrong null (or a null that isn't pinned down independently of the outcome being tested) is itself a failure mode — pre-register what the null construction is *before* running the comparison, not after seeing how close the match looks.

## 4.5 Gate R — mandatory adversarial review before promotion

No claim is promoted to candidate-artifact status without a dedicated adversarial pass checking: (a) function-class match, (b) whether the cited theorem's actual hypotheses hold for this object, (c) whether the claim contradicts anything already on record. A claim that fails Gate R returns to open debt with its specific failure mode recorded — it is not deleted, and it is not silently re-attempted the same way later.

# Part 5 — Occam's Razor Operating Rules

1. **The null model is the default theory, not a strawman to be cleared out of the way.** BM + AS, with no arithmetic substrate assumed, is the current best candidate until something specific beats it. Treat it with the same seriousness as any promoted claim.
2. **Don't build new machinery before checking whether an existing native language already covers the target.** Before reaching for arithmetic's reserved material, check whether calculus, geometry, topology, symmetry, or algebra already supplies whatever is needed for the component in question (Part 2.3's table).
3. **One primary hypothesis per gate, not several unexamined parallel candidates.** When multiple mechanisms target the same open question, designate one as primary and the rest as backups in reserve — developing all of them simultaneously produces an unreviewable backlog, not faster progress.
4. **The symmetric Occam guillotine applies to every pillar, including this checklist.** Arithmetic, BM, AS, and the Reality-First framework itself all carry a standing kill condition. No component is exempt from being cut for redundancy just because it's foundational to the program's own identity.
5. **A negative result that narrows the search is a deliverable, not a failure.** If BM+AS, run to a pre-registered depth, produce no invariant that clears the arithmetic re-entry bar, that is a citable, positive finding — "arithmetic-complete at this depth" — not a stalled program.

# Part 6 — Pre-Flight Checklist for Any New Claim

Run this, in order, before proposing, constructing, or citing anything new:

1. **Which of the four components (Dancer / Dance / Stage / cross-cutting invariant) is this claim about?**
2. **Per Part 2.3, is the mathematics being proposed native to that component, or is it being imported from a branch confirmed silent there?**
3. **If arithmetic is involved anywhere: does the specific quantity pass the three-question test in Part 3.2?**
4. **What debt items (Part 1, item 1) does this claim currently carry, and which are actually being retired by this specific piece of work versus merely restated?**
5. **What is the correct null model (Part 4.4) for this specific claim, and has it been pre-registered before running any comparison?**
6. **Have all load-bearing citations been individually verified against their actual claims (Part 4.3), with provenance flagged for any non-peer-reviewed source?**
7. **Would this claim, if wrong, be caught by an existing kill condition — and if not, what new one does it need?**
8. **Has this exact claim, or a close relative of it, already been rejected and logged? If so, does this attempt address the specific recorded failure mode, or is it a re-run of the same mistake in new notation?**

If any answer is "I don't know" or "I didn't check," that is the next task — not a reason to proceed and check later.

# Part 7 — Governance

1. **External or independent review is required before any claim is treated as settled**, not just internally self-consistent. A claim's own author is the wrong party to certify that it passed Gate R.
2. **The subtraction record is append-only.** Every demotion, rejection, or reversal is logged with its reason at the time it happens — never silently dropped from later summaries.
3. **A prior AI session's summary, another model's transcript, or a previously-generated document is data to be checked, not authority to be inherited.** Apply this entire checklist to inbound material exactly as you would to a claim you are constructing yourself.
4. **When in doubt about scope — is this a standing rule or a one-off instruction, is this claim promoted or merely proposed — default to the more conservative reading** and say explicitly which reading was chosen.
